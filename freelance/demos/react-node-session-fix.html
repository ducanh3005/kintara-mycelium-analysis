Why Your Dashboard Shows Stale Session Data Until Hard Reload (Ctrl+F5)

When a React SPA shows the previous user's data after logout() -> login() and only fixes itself on a full browser reload, the database on Railway is returning the right data—the bug is in in-memory state or HTTP cache surviving the soft client-side route transition.

Cause #1: TanStack Query / SWR Cache Not Cleared Before Route Transition

If you use React Query or SWR, logging out removes the token but leaves the cached ['dashboard'] / ['user'] query data in memory. When User B logs in, React mounts <Dashboard /> and immediately renders User A's cached query while staleTime hasn't expired.

// Inside your logout() handler:
import { useQueryClient } from '@tanstack/react-query';

const queryClient = useQueryClient();

async function handleLogout() {
  await api.post('/auth/logout');
  localStorage.removeItem('token');
  queryClient.clear(); // <-- CRITICAL: wipes all in-memory user queries immediately
  navigate('/login', { replace: true });
}

Cause #2: Axios Instance Capturing Token Once at Module Load

If your API client sets headers: { Authorization: `Bearer ${localStorage.getItem('token')}` } when axios.create() runs at startup, that header stays frozen to User A's token until you press Ctrl+F5 (which re-executes the JS bundle).

// Fix: Read the token dynamically on EVERY request via an interceptor
export const api = axios.create({ baseURL: import.meta.env.VITE_API_URL });

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  } else {
    delete config.headers.Authorization;
  }
  return config;
});

Cause #3: Express API Missing No-Store Headers (Browser Disk Cache 304 Hit)

Express enables ETag by default. Without Cache-Control: no-store on authenticated endpoints, the browser can serve a cached GET response for /api/dashboard until a hard reload forces Cache-Control: no-cache.

// Add this middleware to your authenticated Express routes:
app.use('/api', (req, res, next) => {
  res.set('Cache-Control', 'private, no-store, no-cache, must-revalidate, max-age=0');
  res.set('Pragma', 'no-cache');
  res.set('Vary', 'Authorization, Cookie');
  next();
});

Cause #4: React Reusing Mounted <Dashboard /> State Across Users

Keying your protected layout or dashboard by the authenticated user's ID forces React to unmount and destroy all local state whenever the user ID changes:

<Dashboard key={currentUser?.id ?? 'anonymous'} />
